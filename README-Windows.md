# BookTrip ビルド済みWindows配布版

Node.js・npm・Rollupのインストールや実行は不要です。クラウドでビルドしたHTMLとブラウザ用JavaScriptをEdgeで表示します。ARM64用ネイティブモジュール、EXE、DLLは含みません。

## Windowsで開く

1. https://github.com/satoko-krhs/book-trip-app/releases で **BookTrip-Windows-Built-v0.2.1.zip** をダウンロードします。「Source code」のZIPではありません。
2. ダウンロードしたZIPを右クリックして「すべて展開」を選びます。
3. 展開先の **BookTrip.html** を右クリックし、「プログラムから開く」→「Microsoft Edge」を選びます。通常はダブルクリックでも開けます。
4. 「本の世界を、旅しよう。」と3作品のカードが表示されたら、作品と出発地を選んで旅程を作成します。ターミナルを開く必要はありません。
5. 「管理ツール」も同じHTML内から開けます。管理画面ではURL末尾が `#/admin/travel-times` になります。登録後に「BookTripに戻る」を押すと、作成済み旅程に「マスタ登録値」として反映し、時刻を再計算します。手入力の移動時間・滞在時間は保持します。

BookTrip.htmlにはReact、JavaScript、CSS、画像、初期JSONデータをすべて埋め込んでいます。このファイルは同じ内容のまま別フォルダーへコピーして使えます。基本画面・旅程編集はネット接続不要です。Google Mapsの表示にはネット接続が必要です。

## 企業・組織の管理対象PCについて

Application Control、SmartScreen、Edgeの組織ポリシーなどの無効化や例外設定は不要であり、本手順では案内しません。HTMLやJavaScript自体の表示が組織のポリシーで禁止されている場合は、ポリシーを変更せず、管理者へ承認済みの配信方法を相談してください。

**Windows ARM64実機のEdgeでの表示は未確認です。** クラウドの管理対象Chromiumではローカルファイルの `file://` 表示が `ERR_BLOCKED_BY_ADMINISTRATOR` になったため、設定を変更せずにその検証を中止しました。同一の単体HTMLをHTTPで配信してクラウドのChromiumで操作確認し、読み込み後に通信を切った状態で旅程生成・時間編集を確認しています。これはWindows側のファイル表示ポリシーの許可を保証するものではありません。

## 保存・JSON出力

管理画面で「ブラウザに保存」を押すとブラウザ内へ保存します。ローカルHTMLの保存領域はブラウザやファイルパス、組織の設定に依存し、別PCと共有されません。大切な入力は「JSONをダウンロード」でバックアップしてください。クリップボードへのアクセスが許可されない場合もJSONダウンロードを使用できます。

管理ツールと旅程の画面切り替えでは旅程を保持します。ブラウザ自体の再読み込みでは旅程がリセットされます。作品と地点の関連は未確認、初期移動時間はnullのままです。表示される滞在時間はサンプルであり実測値ではありません。

## ZIPの内容

- `BookTrip.html`: Windowsで直接開くための単体HTML。まずはこちらを使用します。
- `README-Windows.md`: この説明書。
- `THIRD-PARTY-NOTICES.txt`: React等のライセンス。写真の出典・ライセンスは画面下部にも表示します。
- `web/`: `npm run build` で生成した `dist/` の内容。管理者が承認した静的Webサーバーに配置する場合のために同梱しています。サーバーのルートにこの中身を配置し、`/admin/travel-times` を `index.html` へフォールバックしてください。`web/index.html` をダブルクリックする用途ではありません。
- `BUILD-INFO.json`: 元ソースのコミットID等。
- `SHA256SUMS.txt`: 同梱ファイルのSHA-256チェックサム。

ソースコード、node_modules、.env、Windowsで動かすネイティブプログラムは含みません。distをGitのソース管理へ追加せず、ビルド済みファイルだけをGitHub Releasesへ配布しています。

## v0.2.1の使い方

- 旅行条件で旅行日を選択します。各日の経路ボタンの近くに出発日時と「日付をコピー」「時刻をコピー」があります。Google Mapsには自動設定されません。経路を開いて「出発時刻」を選び、表示された日付と時刻を指定してください。日時欄が貼り付けに非対応なら、カレンダー・時刻選択で手動設定してください。コピーが拒否された場合は表示された日時をCtrl+Cでコピーできます。
- 2日プランはDay 1の最後の観光スポットを自動で最終目的地にします。宿泊先は任意入力で、入力した場合だけ観光スポットから宿泊先への移動を追加します。Day 2の出発地には同じ宿泊先を初期設定し、手動で変更できます。宿泊先未入力ならDay 2の出発地を入力してください。
- localStorageのキーは旧版と同じbooktrip-travel-times-v1です。ただし、ローカルHTMLのファイル位置や利用ブラウザが変わると保存領域が異なる場合があります。更新前に大切なマスタはJSON出力で保管してください。

## 移動時間が反映されないとき

1. 旅行者画面の作品を選んでから管理ツールを開きます。作品は自動で引き継がれます。管理側で作品を変更しても、旅行者側の作品・旅程は変わりません。
2. 同じ作品・出発地点・到着地点・交通手段の区間を登録します。新規区間は旅行者画面の交通手段を初期設定します。既存区間が公共交通機関で旅程が徒歩の場合などは、別の区間として登録してください。
3. 実際に確認した移動時間（0以上の整数）と確認日を入力し、確認状態を「確認済み」にします。未確認のまま保存しても自動反映はされません。各区間に不足条件を表示します。
4. 「ブラウザに保存」を押し、保存成功メッセージを確認してから「BookTripに戻る」を押します。「JSONをコピー」「JSONをダウンロード」だけでは旅程用データは保存されません。
5. 旅程の区間に「マスタ登録値」が表示されます。予定時刻を計算するには、出発地→最初のスポットを含む、それまでの全移動区間の時間が必要です。途中の区間だけを保存しても、前の未入力区間があると予定時刻は未確定のままです。帰着予定には復路の時間も入力してください。手動変更済みの区間は「手動設定値」として優先されます。未入力区間は未反映の理由を確認してください。

保存領域が使えない場合は成功と表示せずエラーを表示します。セキュリティ設定は変更せず、ブラウザ・組織が許可する保存方法を確認してください。
